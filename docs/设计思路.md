# 1. 项目一句话定义

> 一个通过浏览器自动化（Playwright）自动探索网站行为，并构建“接口 + 业务流程 + 资源关系图谱”，用于后续安全分析与漏洞推理的系统。

---

# 2. 项目核心目标（非常重要）

这个项目不是传统扫描器，也不是AI问答工具，而是：

```
把一个网站变成一张“可计算的业务关系图”
```

输出能力：

- 网站有哪些接口
- 接口之间如何流转
- 哪些接口依赖 token
- 哪些接口共享资源（orderId/userId）
- 用户完整业务链路（登录→下单→支付）

---


# 4. 核心模块设计

---

# 4.1 Playwright Crawler（浏览器采集层）

## 功能

- 自动访问网站
- 模拟点击 / 路由跳转
- 捕获所有 HTTP 请求与响应

---

## 输出数据结构

```
{  "url": "/api/order/create",  "method": "POST",  "request_headers": {},  "request_body": {},  "response_body": {},  "status": 200,  "timestamp": 123456}
```

---

## 技术点

- page.on("request")
- page.on("response")
- page.goto()
- auto-click exploration（后期增强）

---

# 4.2 API Normalizer（接口归一化）

## 目标

把：

```
/user?id=1/user?id=2/user?id=3
```

统一为：

```
/user?id={id}
```

---

## 输出结构

```
{  "endpoint": "/api/user",  "method": "GET",  "params": [    { "name": "id", "type": "int" }  ]}
```

---

## 方法（无AI版本）

- 数字 → {id}
- UUID → {uuid}
- string → {str}
- 高频路径聚类

---

# 4.3 Schema Extractor（参数结构识别）

## 输入

```
{  "userId": 123,  "email": "a@b.com",  "isAdmin": false}
```

---

## 输出

```
{  "userId": "int",  "email": "email",  "isAdmin": "bool"}
```

---

## 用途

后续用于：

- 自动生成测试数据
- 安全规则匹配
- 参数攻击面识别

---

# 4.4 Graph Builder（核心）

## 核心思想

把接口变成图结构：

```
Node = API / Resource / Token / PageEdge = dependency / flow / auth / data relation
```

---

## 示例

```
login → token → userinfo → order → pay
```

---

## 数据结构（NetworkX）

```
graph.add_node("login", type="endpoint")graph.add_node("userinfo", type="endpoint")graph.add_edge("login", "userinfo", type="token_flow")
```

---

## 关键关系类型

| 类型            | 含义     |
| ------------- | ------ |
| token_flow    | 登录态传递  |
| resource_link | 订单ID流转 |
| workflow      | 业务流程   |
| dependency    | 接口依赖   |

---

# 4.5 LLM Analyzer（可选增强）

## 作用

不是核心，只是“标注器”。

---

## 输入

```
{  "endpoint": "/api/order/create",  "request": {...},  "response": {...}}
```

---

## 输出

```
{  "resource": "Order",  "risk": ["IDOR", "Unauthorized access"],  "description": "订单创建接口"}
```

---

# 4.6 Workflow Builder（业务流程）

## 目标

自动推理：

```
用户行为路径
```

---

## 示例

```

```

---

## 来源

- 请求顺序
- token依赖
- resource流转
